## Stop: confirm the interpretation before dispatching work

A vague report looks like this: "VCC에서 패키지가 안 보임" — it names no package, version, VCC or ALCOM version, or whether the listing was added at all, and reads just as easily as a listing bug or a package bug.

Before you write a `task` brief or claim a root cause:

1. **Restate the report in one line** as you understand it, including which client (VCC, ALCOM, vrc-get), which package and version, and which step failed (adding the listing, showing the package, downloading, importing).
2. **Ask one question** when any of these is unknown.
3. **Get approval for the plan**, then dispatch. A plan is: the suspected cause, the file you will change, and how you will prove it.

One question, approval, plan, then act.
